# deploy/

Everything needed to run Desyn: the hosted deployment (`RUNBOOK.md`) and the self-hosted stack (`SELFHOST.md`).

Hosted production is split in two:

- **Convex Cloud**: the database, realtime sync, functions, HTTP actions (Better Auth, Stripe webhook, Agent API,
  MCP) and file storage. The prod and dev deployments are named in `env/public.env` (`CONVEX_DEPLOYMENT`,
  `CONVEX_DEV_DEPLOYMENT`). Functions are deployed with `convex deploy` from the owner's machine
  (`scripts/deploy.sh`) or from CI (`.github/workflows/convex-deploy.yml`, secret `CONVEX_DEPLOY_KEY`).
- **The shared Hetzner host** (`ssh hetzner`): nginx (TLS, pre-launch basic auth), the Next apps
  (`desyn.app`, `app.desyn.app`, `docs.desyn.app`), the render worker (`render.desyn.app`, called by Convex Cloud
  with the shared secret), backups of the Convex data to S3 and log shipping to Axiom.

Self-hosters keep running Convex themselves: `compose/desyn.selfhost.yml` is a complete stack with a self-hosted
Convex backend, Postgres and MinIO.

## Verify locally

```sh
deploy/scripts/lint.sh     # shellcheck, python syntax, compose config, nginx -t (incl. a coexisting "other
                           # site"), actionlint, vector validate + transform tests
deploy/tests/run.sh        # contracts, server-env, sandboxed bootstrap/certs/deploy/backup/rollback flows,
                           # nginx behaviour with a real nginx (NGINX_BIN=...)
```

Without a reachable Docker daemon, point lint.sh at local binaries:
`NGINX_BIN=... VECTOR_BIN=... SHELLCHECK_BIN=... ACTIONLINT_BIN=... deploy/scripts/lint.sh`.
CI runs both in `.github/workflows/ci.yml` (jobs `deploy-config` and `deploy-tests`).

## Contract for app/crate owners

- Next apps: `output: "standalone"` (the image also sets `NEXT_PRIVATE_STANDALONE=1` as a default), listen on
  `PORT` (3000 in the image; the web containers get `PORT=4100`), no CSP/HSTS headers from the app (nginx sets them
  per host: `nginx/desyn/snippets/csp-*.conf`; extend them there when a new origin is needed). `/` must answer
  without a 5xx (redirects are fine): it is the healthcheck. Runtime env comes from `env/server/<app>.env`; add a
  line there (and a source in `public.env` or `.env.keys`) when an app needs a new variable.
- Next apps run on a read-only root filesystem (only `/tmp` and `.next/cache` are writable tmpfs). ISR/revalidated
  pages still work from Next's in-memory cache, but apps that revalidate should set
  `experimental.isrFlushToDisk: false`.
- The browser talks to Convex Cloud directly (`NEXT_PUBLIC_CONVEX_URL`, websocket `wss://<deployment>.convex.cloud`,
  allowed in the app and landing CSP). The web app proxies Better Auth (`/api/auth/*`) to
  `NEXT_PUBLIC_CONVEX_SITE_URL` itself (Next route handler), so cookies stay first-party; nginx forwards the
  visitor address as `X-Real-IP` / `X-Forwarded-For` (client values are replaced, never appended).
- `app.desyn.app/api/v1/*` (Agent API) and `/mcp`, `/mcp/*` (MCP) never reach the web app: nginx passes them
  straight to the Convex Cloud site URL (`nginx/desyn/snippets/convex-site.conf`; TLS verified, DNS re-resolved
  through `desyn/local/resolver.conf`), without basic auth or the gate cookie, rate limited per address. The web
  app must not define routes under those paths. Other `/api/*` paths go to the web app.
- Worker: binary `desyn-worker`, listens on `0.0.0.0:$PORT` (8080), `GET /healthz` (2xx), fonts from `FONTS_DIR`,
  ffmpeg at `FFMPEG_PATH`, writes only to `/tmp`, checks `x-desyn-secret` against `RENDER_WORKER_SECRET` in
  constant time and answers 401/403 to a wrong secret (healthcheck.sh fails the deploy if a wrong secret is
  accepted). Convex Cloud reaches it at `RENDER_WORKER_URL=https://render.desyn.app`; nginx exposes only
  `POST /v1/{render,thumbnail,describe,layout,measure,apply}` and `GET /healthz`, bodies up to 64 MB.
- Convex: functions in `convex/` must pass `convex deploy --typecheck enable`; every package they import must be a
  dependency of the root `package.json`; Node built-ins only in `"use node"` files. Function env is pushed by
  `scripts/convex-cloud-env.py` (names in docs/SPEC.md section 9); add new names there. A deploy pushes functions
  before the services roll, and a failed rollout does not revert them: keep schema and function changes
  compatible with the previous release (expand first, contract in a later release).
