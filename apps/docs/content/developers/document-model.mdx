Every package that touches a design follows one contract, `docs/DOCUMENT_MODEL.md`. The type excerpts on these pages are rendered from that file when the docs are built, so they always match it exactly.

Key properties:

- **Flat and addressable.** A design is a flat map of nodes keyed by id; the tree is expressed with `parent` and ordered `children`. Any node can be read or patched directly.
- **JSON, camelCase.** The TypeScript definitions are the source of truth; `@desyn/schema` derives zod and JSON Schema from them and `desyn-core` mirrors them with serde.
- **Canonical.** A canonical JSON form (sorted keys, normalized numbers) is used for hashing, conformance fixtures and comparisons.
- **Versioned.** `schema: 1`. Changes are additive and recorded in the contract's change log.

## Design

The top-level object. `nodes["root"]` is the root node; its children are the page ids, in order.

<Generated name="model-types" names="Design,DesignKind,AssetRef,DesignStyles" />

Anywhere a `Color` is expected, a value may instead reference a variable or a color style:

```json
{ "type": "solid", "color": { "$var": "brand.primary" } }
```

```json
{ "type": "solid", "color": { "$style": "c0l0rst7le01" } }
```

Assets are referenced by id from nodes (`ImageNode.assetId`, image fills, SVG and video nodes). `AssetRef.url` is filled in by clients at load time and never persisted; `storageKey` is the server-side truth.

## Invariants

These hold after every transaction. Operations that would break them are dropped, never applied partially.
