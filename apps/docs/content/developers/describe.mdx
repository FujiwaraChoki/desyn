---
title: Describe (AI view)
description: The semantic description of a page that the AI reads — tree in page coordinates, palette, fonts, typographic scale, alignment grid, hierarchy and lint issues with fixes.
---

`describe` turns a page into a compact, structured summary — the way a designer would read it — instead of raw JSON. The agent reads it before every edit, and you can use it for your own analysis, accessibility checks or design linting.

It is computed deterministically by the Rust core (`desyn_core::describe`, no model call involved) and exposed by the wasm engine in clients, by the render worker at `POST /v1/describe`, and by the Agent API at [`GET /designs/{designId}/describe`](/developers/api/designs#describe-a-page).

## Input

The design, plus optionally a `pageId` (default: first page), the current `selection`, a `maxDepth` for the tree and whether to include styles.

## Output

<Generated name="model-types" names="Description,DNode,Issue,IssueCode" />

- **tree** — the page's layers in **page coordinates** (rotation and parents already resolved), keeping z-order back to front. Text nodes include their text and font summary; images include their kind (photo, illustration, logo, icon).
- **palette** — dominant colors by share of area.
- **fonts** — families with the weights used and how many nodes use them.
- **typography** — the font size scale in use, the headline and body sizes and their ratio.
- **grid** — inferred page margins, alignment lines shared by several nodes, and the dominant spacing rhythm.
- **hierarchy** — nodes ranked by visual weight (size, contrast, position) with the reason.
- **issues** — lint results, each with affected ids, a message and often a ready-made `fix` as a list of operations.

## Grouping inference

The `semantic` field describes what a group of nodes means — *"product card: image + title + price + button"*, *"list of 4 equal items"* — inferred from containment, proximity and role patterns. Inference is heuristic but deterministic. Explicit [roles](/concepts/roles) and names always win over inference.

## Lint codes

| Code | Means |
| --- | --- |
| `low-contrast` | Text contrast below WCAG AA for its size |
| `tiny-text` | Text too small for the design kind |
| `text-overflow` | Text does not fit its box |
| `off-page` | Content outside the page (and bleed) |
| `overlap` | Unintended overlap between elements |
| `misaligned` | Almost, but not exactly, aligned with neighbors |
| `uneven-spacing` | Spacing between similar elements differs |
| `orphan-line` | A single word on the last line of a paragraph |
| `too-many-fonts`, `too-many-colors` | More families or colors than the design can carry |
| `weak-hierarchy` | No clear most-important element |
| `image-low-res` | An image will look soft at its size or in print |
| `unsafe-margin` | Content inside the safe margin for the kind |
| `missing-alt` | An image without alt text |
| `unlabeled-group` | A group with no meaningful name or role |
